# LinguaWiki glossary

- **Core** — the generic Python package, contracts, migrations, skills, templates, and synthetic fixtures in this repository.
- **Language pack** — an independently versioned, capability-driven bundle of reusable language content, frameworks, assessments, activity templates, and resource metadata.
- **Learner workspace** — one private, independent Git repository for a learner/program. It pins released core and packs; it is not a normal fork of core.
- **DuckDB authority** — the local database is the source of truth for mutable learner objects. Generated Markdown is never authoritative.
- **Wiki projection** — deterministic, sanitized Markdown rendered from authoritative database state and suitable for reviewed private Git history.
- **Skill** — Codex instructions that orchestrate a learning or maintenance workflow through typed CLI commands.
- **Session package** — a provider-independent `lingua.session.v1` interchange package containing transcript layers, events, and external artifact references.
- **Evidence** — an atomic, provenance-bearing observation of learner performance in a particular task, modality, assistance condition, and time context.
- **Pack maturity** — an explicit capability/coverage state such as `fixture`, `pilot`, `onboarding-ready`, or `placement-ready`; it is not a claim about learner mastery.
- **Framework** — a pack-declared proficiency system whose levels and prerequisites are interpreted by that pack rather than globally by core. A level label belongs to exactly one framework; core never relates two.
- **Content address** — the checksum over a pack's manifest and every other file in its directory. It identifies a pack *version* by its bytes, so the same version can never hold different content.
- **Stable key** — an author-chosen, permanent identifier for one pack item inside its kind. A content ID is derived from `(pack key, kind, stable key)`, so renaming a key creates a new item and orphans the old one's learner state.
- **Origin class** — how a persistent item came to exist: `authentic-source`, `learner-produced`, `source-derived`, `ai-adapted`, `ai-generated`, `synthetic-media`, or `human-authored`. Independent of every review axis.
- **Review axis** — one of five independent questions asked of an item: linguistic, pedagogical, source-alignment, rights, privacy. Each has its own ordered state vocabulary, because the words mean different things per axis.
- **Risk tier** — 0 to 4, from an ephemeral drill to redistributable pack content. Together with the target lifecycle it sets the minimum review strength each axis needs.
- **Promotion gate** — the check that an item's declared lifecycle is one its own review states support. Failing it names each unmet axis rather than reporting a single verdict.
- **Generation batch** — one bounded drafting run through a versioned prompt template, carrying the sampling policy and inspection duty fixed when it opened. A defective sample quarantines the batch, its template, and everything downstream.
- **Declared level** — a level the learner names, stored as a low-confidence hypothesis. It decides which material to prepare and establishes nothing about what the learner can do.
- **Calibration** — a bounded, labelled probe against a pack whose bank cannot support comprehensive placement. Reported as a calibration, never as a placement.
- **Not tested** — a dimension no task or no available modality could probe. It is a gap in the evidence, never a failure by the learner.
- **Attempt** — what happened: one task, its modality, the help given, the delay, who judged it, and how sure they were. Immutable; a correction is a new attempt, not an edit.
- **Served snapshot** — the copy `assessment_run_tasks` keeps of what a task demanded at the moment a run served it: its type, modality, dimension, difficulty, family, content hash, and the items it targeted. A pack is mutable and a run is not, so this, not the pack's current record, is what a learner's history rests on. It is whole or wholly absent; a partial record is damage, and unknown targets are not permission to attribute an item observation to the task.
- **Evidence claim** — what an attempt justifies, which is not the same as what it scored. `recognition`, `comprehension`, `controlled-production`, `spontaneous-production`, `delayed-transfer`, or `intelligibility`. Each declares the modalities and task types that can produce it.
- **Claim ceiling** — the highest mastery stage a claim can ever justify. It is applied *after* the promotion gates, which is what makes it impossible for recognition to promote production however often it succeeds.
- **Mastery stage** — `unseen`, `encountered`, `recognized`, `understood`, `controlled-production`, `spontaneous-production`, `stable`. Computed from evidence and recomputable from it; never set directly.
- **Context key** — the setting an observation happened in, and the unit diversity is counted in. Two successes on the same prompt are one observation repeated.
- **Help level** — `none`, `prompted`, `hinted`, `scaffolded`, `full-answer`, ordered by how much was given away. Full help leaves nothing positive to have observed.
- **Retrieval class** — `immediate`, `same-session`, or `delayed`. A claimed delay must be a real one, because delayed evidence is the strongest kind there is.
- **Error pattern** — a recurring mistake, identified by `(track, category, normalized signature, target item)`. Signatures too close to dismiss and too far to merge are reported for review rather than merged.
- **Counter-evidence** — a success that argues against a recorded error, qualified as `controlled`, `novel`, `spontaneous`, or `delayed`. Derived from the evidence row, never asserted, and one success never resolves anything. `controlled` and `spontaneous` are terms about *production*: they require the learner to have produced language rather than chosen between offered options, so receptive evidence cannot retire a production error.
- **Unconfirmed error** — a pattern whose every occurrence so far was a transcription artifact, or was classified uncertain. It is on the record and counted against nobody: a mishearing taught back as a mistake is worse than a mishearing lost.
- **Estimate status** — `not-tested`, `provisional`, or `estimated`. It separates "nobody looked" from "one observation" from "independent observations agree"; a confidence label alone conflates the three.
- **Context bundle** — a bounded, scope-declared set of learner facts assembled for an agent to act on. Whatever does not fit is reported in `omissions` with its count, so a short list and a truncated one look different. The record limit bounds the assembled bundle, not each section independently.
- **Policy version** — the identifier of the rule set that produced a row: `evidence.v1`, `mastery.v1`, `error.v1`, `estimate.v2`, `placement.v1`. Stored on the row, so a policy change can be told from a data change and replayed.
- **Session** — one sitting: a plan, its blocks, the observations it staged, and the close that credited them. `planned → active → closing → completed | partial | abandoned`, and `closing` is durable so an interrupted close is distinguishable from one nobody attempted.
- **Block** — one scheduled part of a session, with a role (`warm-up`, `core`, `closure`), a type, an area, a resolved dimension, a modality, planned minutes, and the reasons it was chosen. The warm-up and the closure frame every session and never introduce new material.
- **Dimension kind** — `receptive`, `form`, `productive`, or `pronunciation`: what a block produces evidence *about*. The dimension *names* belong to the pack, so core names the kind and resolves the name from the pack's declarations.
- **Batch (flush)** — one bounded set of observations from one block, stored durably by `session log` with a sequence number, a content hash, and an idempotency key. It changes nothing about the learner. The same key with the same content is stored once; with different content it is a conflict.
- **Staged event** — one provisional observation, kept as it arrived and, after a close, naming the durable row it became. Nothing is edited into place: the staged row is the audit trail of what the close was given, which is why the retention rule is applied *before* it is written rather than when the observation is finally credited.
- **Source event identity** — the identifier the producer gave an observation: a skill's own event ID, or an external session's. It is what makes an observation *the same observation* across a retried flush, an overlapping checkpoint export, and a re-ingested package, none of which a staged row's own key can express. Unique per session, and checked across an external session's packages.
- **Occurrence time and flush time** — when the learner did the thing, and when it was sent. Both are stored, and every derived fact is built from the first: the delay class, whether a repeat is a repeat, when an error was last seen, which estimate snapshot an observation falls into.
- **Close** — the single transaction that materializes a session's staged work into attempts, evidence, error occurrences, follow-ups, and notes, and marks the projection stale. Each event is resolved *inside* that transaction, in the order it happened, so the second correction of one pattern is its second occurrence rather than another first. Its result is stored, so a close whose response was lost is retried and returns the original answer rather than doing the work twice.
- **Partial close** — a close of a deliberately shortened session. Valid staged work is credited; the objectives of blocks nobody reached are not, and a reviewed block can be excluded by name with its reason kept.
- **Abandoned session** — a session credited to nothing whose staged work is kept for audit. `session recover` can move those observations into a new session after explicit review; the originals are marked as recovered so nothing counts twice.
- **Novelty cap** — the most previously unseen targets one session may introduce, scaled by its length and reduced by low reported energy. A promise about the whole session, counted over distinct items rather than per block.
- **Session package** — a whole session produced elsewhere (`lingua.session.v1`), with its transcript layers and artifacts, ingested and *staged* rather than trusted. Deduplicated by canonical content, so the same conversation exported twice is one session.
- **Evidence basis** — whether an observation rests on the learner's audible performance (`audio`), on a text of it (`transcript`), or on direct observation in a running session (`direct`). A pronunciation claim is confirmable from audio and never from a transcript.
- **Projection** — a generated rendering of the database under `wiki/`, marked as generated, hashed so drift is detectable from the database side, and never a source of truth. `session close` marks it stale; only `wiki build` clears that.
- **Source** — one work the learner uses: a course, a book, an article, a podcast, a video, a conversation, or something they wrote. Catalogued per *track* rather than per workspace, because progress and comprehension are facts about a learner's relationship with the material rather than about the material.
- **Rights class** — what may be stored from a work: `metadata-only` (title, author, where it is — no text at all), `short-excerpt` (a bounded quotation that justifies an observation), or `full-local` (the learner's own, or theirs to hold). Checked before an excerpt is written and asserted again over the data, because a copyright boundary crossed inside a learner's database cannot be found by reading the code.
- **Comprehension aid** — how much help the learner had: `unaided`, `glossed`, `subtitled`, `translated`, `explained`. Ordered, and the order is the evidence — an unaided reading recorded *after* an aided one is not a second observation but the first one with the help left out, so it is refused at the command and at the close.
- **Comprehension band** — `none`, `little`, `gist`, `most`, `full`. An ordered policy vocabulary, never compared alphabetically: `max()` over the strings would rank `none` above `gist` and report a learner who understood nothing as having understood the most.
- **Study mode** — `intensive` (a short passage worked closely, where extracting items is the point) or `extensive` (volume for gist, where a harvest of extracted items means the work was intensive and mislabelled).
- **Coverage** — the share of a source's units the learner has *completed*, or `None` when the total is unknown. Completing a unit twice does not advance it twice: a reread is not more of the source.
- **Transcript layer** — `raw` (what the transcription produced, immutable), `normalized` (punctuation, casing, fillers — the words are the same words), `reviewed-hearing` (a person listened again). Kept apart because "did the learner say that, or did the machine hear it?" decides whether they are corrected for a mistake they never made.
- **Revision kind** — what a later reading of an utterance claims it did: `normalization` (nothing but punctuation and casing changed, and it is held to that) or `hearing` (different words were heard). Derived from what actually changed rather than accepted on assertion.
- **Interpretation classification** — `learner-error`, `transcription-artifact`, or `uncertain`. Only the first counts against the learner, and it requires a corrected form: a mark with nothing to learn from it is refused.
- **Acoustic claim** — a judgement about how something *sounded*, in one of `intelligibility`, `phonetic-accuracy`, `prosody`, or `native-likeness`. `confirmed` requires audio in every dimension; prosody and native-likeness require it at every status, because the words of a question and the words of a flat statement are the same words.
- **Artifact** — a file that stays outside Git and outside the database — a recording, an export — with a row naming its path, its checksum, and whether the learner consented to keeping it. A *not retained* row records that a file existed and was not kept, which is a different fact from there never having been one.
- **Purge** — deleting an artifact and settling what depended on it. The file goes, a tombstone with its reason stays, and exactly the acoustic claims that needed the sound are invalidated — marked, not deleted. Nothing else is: what the learner *said* was established by the transcript, which is still there.
- **Privacy audit** — the check that asks what is about to escape: files that could reach Git, the learner's own words or restricted source text found in committed pages or in the audit log, the retention position stated plainly, and what purging each held recording would cost — before anyone purges one.
